# 404 chat help — 0.12.0

## Behavior

**Dzen Chat → Widgets → Show chat on 404 pages** is an opt-in setting, saved
separately from widget selection. On a WordPress 404 response, the plugin uses
the enabled site-wide widget and offers **Start a conversation**. The invitation
appears only after the service launcher is available. It can be dismissed and
stays hidden after opening or closing chat during that page visit. No message is
sent automatically. Regular pages keep their existing placement behavior.

With the setting off, or with no selected/available widget, the 404 response
includes neither the widget nor the invitation. The theme, URL and HTTP 404 status
are preserved. The invitation uses the WordPress site language; the admin setting
uses the administrator's locale. Service-rendered chat retains its own language.

## Local browser and HTTP verification

Real integration: `https://local.dzenchat.com:8869/?p=2147483647`.

- The missing post returns HTTP 404 with or without chat enabled. An anonymous
  HTTP request confirms the mount and deferred service loader are present only
  when enabled; the local invitation script follows the service loader.
- Enabled and saved the setting through the real WordPress admin. The browser
  displayed the invitation and one real launcher. **Start a conversation** opened
  the service iframe and its message composer, carrying the missing page URL.
  No test message was sent.
- Closing the real chat did not reopen the invitation. Dismissal hid the invitation
  without opening chat and returned keyboard focus to the launcher.
- At 843 × 863, the invitation fits within the viewport. At 375 × 700 it also
  fits, without horizontal page overflow. The existing WordPress toolbar
  accommodation remains in effect for the service window.

Isolated fixture: `http://127.0.0.1:8870/404/`.

- This URL now returns an actual WordPress 404. English and Russian admin settings
  and the public Russian invitation were checked in the browser. Its CTA opens
  the explicitly labelled demo panel, with no real AI requests.
- Unchecking and saving removed the complete embed from an anonymous HTTP 404
  response; re-enabling restored it.
- Restored the original English site language and site-wide widget selection after
  testing. Left 404 help enabled on both local sites for review.

The real site's plain permalink configuration serves `/404/` as a normal home
page with HTTP 200; a nonexistent post ID was therefore used for the real 404
check. The plugin uses WordPress `is_404()`, not the URL's spelling.
These checks do not claim production deployment or a new AI-answer quality test.

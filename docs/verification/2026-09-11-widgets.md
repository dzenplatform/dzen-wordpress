# Виджеты WordPress 0.3.0

Контракт сверён с реализацией задачи Codex
`01a086d7-18f2-73e1-99b0-b59d123f2da5`: модели запросов и ответов, обработчики
и Bearer-аутентификация. Основной проект Dzen Chat не изменялся.

## Реализовано

- Чтение списка и отдельного виджета, создание, переименование, включение,
  выключение и настройка уточняющих вопросов через `/api/widgets`.
- Отдельный выбор виджета для WordPress, переопределение и скрытие на странице
  или записи. Глобальное включение относится ко всему проекту Dzen Chat.
- Публичный loader `/widget/{code}` с одним контейнером `#chat-chat`.
  В браузер отправляется только публичный код виджета.
- Кеш на пять минут, привязанный к клиенту, сайту и сервису. Изменения через
  плагин обновляют его сразу; публичное обновление ограничено тремя секундами,
  после ошибки повторяется не чаще раза в минуту.
- Проверка фактического ответа перед уведомлением об успешном сохранении.
  Ошибки доступа, отключённый виджет и некорректный ответ не дают новый embed.
  Форма, открытая до удаления ключей, предлагает подключить сайт заново.

Регистрация и защищённое хранилище сохранены. Индекс, диалоги, источники,
управление триггерами и биллинг в этой итерации не подключались. Из успешного
ответа виджетов не выводится состояние оплаты проекта.

## Автоматические проверки

- PHP lint всех runtime-файлов — успешно.
- 48 базовых, 40 виджетных и 36 регистрационных проверок — успешно.
  Они используют отдельный WordPress и синтетические ответы по реальному
  контракту; успешные проверки не подтверждают работу сервера Dzen Chat.
- Проверены точные пути и JSON, Bearer без HMAC, TLS без редиректов, истечение
  кеша и восстановление после ошибки, отключение с сервера, клонирование сайта,
  nonce и права, недоступный/чужой ID, минимальные поля создания и изменения,
  исключения страниц, отсутствие секретов и обращений к `/api/v1`.
- Шесть проверок упаковки — успешно. Собраны `dzen-chat-0.3.0.zip` и SHA-256;
  в пакет входят runtime-файлы, включая `src/Widgets.php`, без fixture,
  тестовых ключей, Docker, локальных сертификатов и отчётов.

Команды для изолированного стенда:

```sh
COMPOSE_PROJECT_NAME=dzen-wordpress-widget-tests DZEN_WORDPRESS_PORT=8870 make test
make package-test
make package
```

Установка WordPress и fixture описаны в README. Настоящее подключение в проекте
Compose `dzen-wordpress-registration` сохраняется в других volumes.

## Проверка интерфейса

Во встроенном браузере проверен `http://127.0.0.1:8870`, отдельный WordPress
с явно обозначенным тестовым API. Из админки выполнены создание второго
виджета, переименование, изменение подсказок, включение/выключение, выбор
другого виджета и снятие общего размещения.

На публичной странице проверены исчезновение и возвращение loader после
отключения/включения, правильное название выбранного виджета в тестовой панели
и отсутствие дубликатов. После выхода из WordPress панель администратора
отсутствует, а контейнер и скрипт виджета присутствуют в единственном экземпляре.
Ответы ИИ и реальный loader Dzen Chat этот стенд не проверяет.

## Граница живой проверки

Сохранённая настоящая регистрация доступна в WordPress на
`https://local.dzenchat.com:8869`. Страница виджетов открыта с этим подключением:
реальный `GET https://local.dzenchat.com/api/widgets` возвращает HTTP 500.
На `https://local.dzenchat.com/api-docs/` пока показан только старый
`POST /api/update`; новые методы доступны в коде указанной задачи, но не на
проверенном локальном сервисе.

Полный цикл с настоящим API и loader остаётся непроверенным до запуска новых
методов. Основной сервис не перезапускался и не заменялся другим checkout.
Production-деплой и публикация релиза 0.3.0 не выполнялись.

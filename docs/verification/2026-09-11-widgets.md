# WordPress 0.3.0 widgets

The contract was checked against request/response models, handlers and Bearer
authentication in Codex task `01a086d7-18f2-73e1-99b0-b59d123f2da5`.
The main Dzen Chat project was not changed. This historical report predates
the successful real API checks in the 0.4.0 report.

## Implemented

- List/read/create/rename/enable/disable widgets and configure follow-up questions
  through /api/widgets.
- Separate WordPress site placement, page/post overrides and page hiding.
  Global enablement applies to the entire Dzen Chat project.
- Public /widget/{code} loader with one #chat-chat container.
  Only the public widget code reaches the browser.
- Five-minute cache bound to client, site and service. Plugin changes refresh
  immediately; public refresh has a three-second timeout and retries after
  errors at most once per minute.
- Validate the actual response before reporting a saved change. Access errors,
  a disabled widget or malformed response do not produce a new embed.
  A form opened before credential removal asks the user to reconnect.

Registration and secure storage are preserved. Index, conversations, sources,
trigger management and billing were not connected in this iteration. A successful
widget response does not imply that a project is paid.
